## 🚀 التشغيل الفوري

اللعبة مبنية بـ HTML/CSS/JS نقي **بدون أي خطوة بناء (Build)** — تفتح مباشرة:

```bash
# من داخل مجلد المشروع:
npx serve -s . -l 8080
# ثم افتح: http://localhost:8080
```

> **ملاحظة:** للاختبار المحلي الأمثل فعّل الملفات عبر خادم محلي (كما أعلاه) وليس بفتح الملف مباشرة.
> بدون ربط قاعدة البيانات، تعمل اللعبة في **وضع تجريبي محلي** كامل الوظائف (تُحفظ النتائج في متصفحك فقط) حتى تربط Supabase.

## 🗄️ ربط قاعدة بيانات حقيقية مشتركة (Supabase — مجاني)

حتى يرى كل طالب نفس اللوحة من أي جهاز:

1. أنشئ حسابًا مجانيًا على [supabase.com](https://supabase.com) ثم مشروعًا جديدًا.
2. من **SQL Editor** داخل المشروع شغّل هذا الملف كاملًا بالترتيب:
   - `supabase/schema.sql`
   - `supabase/seed_questions.sql`
3. من **Project Settings → API** انسخ:
   - `Project URL` (مثال: `https://xxxx.supabase.co`)
   - `anon public key` (مفتاح علني بطبيعته — ليس سريًا)

### الطريقة الموصى بها للنشر: GitHub Secrets (بدون أي قيم في الريبو)

القيم تُحقن وقت النشر عبر `.github/workflows/deploy.yml` وتكتب إلى `js/supabase-env.js` آليًا:

```
الإعداد → Settings → Secrets and variables → Actions → New repository secret:
  SUPABASE_URL       = https://xxxx.supabase.co
  SUPABASE_ANON_KEY  = eyJhbGciOi… (anon public key)
```

احفظهما ثم أعد النشر (Push أو `workflow_dispatch`) — لا يُرفع أي مفتاح مع الموقع.

### أو الطريقة المباشرة (لعجلة النشر بدون CI)

ضع القيمتين يدويًا في `js/supabase-env.js` ثم ادفع التغيير:

```js
export const SUPABASE_ENV = {
  url: 'https://YOUR-PROJECT.supabase.co',
  anonKey: 'YOUR-ANON-PUBLIC-KEY', // anon key علني وليس سريًا
};
```

> ⚠️ أثناء التطوير المحلي قبل ربط Supabase تعمل اللعبة في **وضع تجريبي محلي** كامل
> (تُحفظ النتائج في متصفحك فقط) — يتحول تلقائيًا إلى القاعدة الحقيقية عند توفر القيم.

### تغيير الألغاز لاحقًا؟
عدّل `js/data/questions.js` ثم أعد توليد ملف البذور ليظل التحقق من النقاط على الخادم متزامنًا:

```bash
node tools/generate-questions-seed.mjs
# ثم طبّق supabase/seed_questions.sql الجديد في Supabase SQL Editor
```

## 🌐 النشر على GitHub Pages (رابط عام)

الريبو: **`joudaraljani/kharij-al-sanduq-game`** — الرابط النهائي:
`https://joudalarjani.github.io/kharij-al-sanduq-game/`

البنية: **GitHub Pages → Web Game → Supabase → Leaderboard مشترك**.

1. ارفع المشروع إلى GitHub (تم بالفعل — workflow جاهز في `.github/workflows/deploy.yml`).
2. من إعدادات الريبو: **Settings → Pages → Source: "GitHub Actions"** (النشر يتم بالـ workflow تلقائيًا).
   - لا حاجة لتحديد فرع — البث من `main` يشغّل النشر تلقائيًا، ويوجد خيار يدوي `workflow_dispatch`.
3. أي **Push** إلى `main` ينشر تلقائيًا بعد دقائق، مع **بوابة جودة** (اختبارات المنطق) قبل النشر.
4. أضف Secrets الخاصتين بـ Supabase أعلاه حتى ترى اللوحة مشتركة لجميع الطلاب.

> **لماذا يعمل في أي مسار فرعي؟** كل الروابط داخل الموقع نسبية (نسبية بين المجلدات
> في HTML ووحدات ES Modules)، فلا يتأثر بالحساب الفرعي، وتم التحقق محليًا بمحاكاة
> مسار `/repo-name/` لـ **28 أصلًا ووحدة (200 OK)**.

| مزود بديل | الطريقة |
|---|---|
| **Netlify** | سحب مجلد المشروع إلى الداشبورد مباشرة (إضافة Secrets كـ Environment Variables) |
| **Vercel** | `npx vercel` ثم تحديد المتغيرات `SUPABASE_URL` / `SUPABASE_ANON_KEY` |

## 🔐 الأمان ومنع التلاعب (وما هو ممكن تقنيًا)

نظام من ثلاث طبقات:

1. **النقاط لا تأتي من المتصفح**: يرسل العميل أحداث اللعب (السؤال المختار، الإجابة، الأزمنة)، وتقوم دالة `submit_game` في Supabase **بإعادة حساب النقاط من الأحداث** بمطابقتها بجدول `question_map`، فلا يمكن للاعب تغيير نتيجته بتزوير القيمة.
2. **قيود على الخادم**: حد أقصى 5 محاولات لكل اسم/ساعة، أرقام ومؤشرات متحقق منها، ومدة قصوى 900 ثانية.
3. **RLS + إدراج فقط**: الجداول معزولة وكل الكتابة تمر عبر دوال `SECURITY DEFINER`.

**القيود التقنية الواجب معرفتها (وينقصها أي تطبيق بلا خادم ألعاب مخصص):**
- قوانين اللعبة تعمل في المتصفح، فالمستخدم المتمكن تقنيًا قد يقرأ الكود أو يغيّر أحداث اللعب. الحماية العملية المطبقة (إعادة الحساب على الخادم + الحدود + الأسماء المعقّدة) تمنع التلاعب السهل وتحافظ على نزاهة التحدي، وهي أقصى حماية ممكنة ضمن هذه البنية وحد التكلفة المجانية.
- لمنع 100% من التلاعب سيلزم تشغيل محرك اللعبة كاملًا على خادم (Edge Functions/WebSocket) — ممكن كمرحلة ثانية إن لزم.

**حماية المحتوى:** أسماء اللاعبين تُنقّى من أي HTML/JavaScript قبل التخزين (أمامي + خلفي) وتُعرض مهربَة (escaping)، مع حدود الطول.

**المفاتيح السرية:** لا يوجد أي مفتاح سري في الكود المنشور. `anonKey` علني بطبيعته في Supabase (المقيد بـ RLS)، وأي مفتاح سري (مثل Service Role) يبقى عندك ولا يُرفع مع الموقع أبدًا.

## 👨‍💻 لوحة الإدارة

رابط الإدارة بعد النشر: `https://joudalarjani.github.io/kharij-al-sanduq-game/admin.html`

افتحه في **متصفحك أنت** (لا تضع الرابط في أي مكان عام) وأدخل:
1. كلمة المرور المرقبة (غيّرها في `js/admin-config.js`).
2. عند ربط Supabase: أدخل **Service Role Key** يدويًا في كل جلسة (يبقى في الذاكرة فقط ولا يُخزن).

تشاهد: عدد المشاركين الفريدين، المحاولات، التقييمات، متوسط النجوم، جدول المشاركين بالترتيب، وجدول الاقتراحات.

> ملاحظة أمنية: كلمة مرور الصفحة الأمامية طبقة شكلية. الأمان الحقيقي أن الصفحة غير موصولة من أي مكان، وأن مفتاح الخدمة لا يُخزن. لمصادقة حقيقية (Supabase Auth) يمكن إضافتها لاحقًا كمرحلة ثانية.
